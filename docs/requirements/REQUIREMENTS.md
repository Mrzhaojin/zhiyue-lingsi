## 1. 背景与问题

现有项目是一个「阅读 + 社区 + AI」的单页应用。原始版本以演示为目标：数据只存在浏览器、AI 直接调用第三方、文档中的数据库/并发/同步描述与实现不符。

重构要解决的问题不是「再加几个页面」，而是：

1. **数据不可靠**：单 JSON 全量覆盖、配额溢出无提示、换设备即丢失；
2. **身份不统一**：登录身份与内容归属是两套 id；
3. **工程不可维护**：无测试、无 CI、无分层边界、密钥硬编码；
4. **能力不可信**：推荐/流式/翻译等描述超出实现。

## 3. 产品定位与范围

### 3.1 定位

**离线优先的 AI 阅读工作台**：以「书 → 读 → 记 → 讨论」为主链路，AI 作为阅读过程的辅助，而不是独立聊天产品。

### 3.2 范围内

- 邀请制、≤50 名活跃用户的单实例应用（Q1）；
- 单机可用的阅读、笔记、社区与 AI 辅助；
- 数据可备份、可迁移、可恢复；
- 可通过配置切换「本地演示 / 云端认证」；
- 可部署到自有服务器（单机）。

### 3.3 明确不做（至少本阶段）

- 实时多人协作 / IM / 推送；
- 付费、会员、广告；
- 原生 App；
- 依赖推荐算法作为核心卖点（数据量不足，做了也无法证明效果）；
- 内置非公版书籍全文。

## 6. 约束与假设

1. 单人维护，无专职运维；方案必须简单可运维。
2. 先本地跑通，再部署到自有服务器；云端能力可后置。
3. AI 预算有限：必须有限流、缓存与配额。
4. 书籍内容受版权限制：只使用公版/授权/演示摘录。
5. 浏览器环境：现代浏览器，暂不考虑 IE/旧版 Safari。

## 8. 已确认决策（v1.0）

| 编号 | 决策 | 对设计的影响 |
|---|---|---|
| Q1 | **小范围邀请（≤50 活跃用户）** | 单实例足够；需要邀请码、基础审核与配额；不做分片/多租户隔离 |
| Q2 | **先还 M1.5 工程债，再做 M2（RLS）** | 顺序：数据层拆分 → 云端 + RLS → AI |
| Q3 | **公版书/授权摘录，标注来源** | Book 增加 source/license/attribution；清理伪造章节；导入能力后置 |
| Q4 | **赏析+问答做扎实，再加 RAG** | 需要语料切分、向量/关键词检索、引用与评测集 |
| Q5 | **按量付费，设每日/每用户上限** | BFF 必须有配额、成本统计与降级 |
| Q6 | **腾讯云 + 宝塔（Linux）** | Nginx 静态站 + Node BFF（PM2/宝塔管理）+ HTTPS + 定时备份 |
| Q7 | **无硬 deadline，按工程质量推进** | 以可维护性/正确性为验收标准，不砍测试 |
| Q8 | **本地不加密** | 威胁模型以设备与账号为前提；导出文件由用户自行保管 |
