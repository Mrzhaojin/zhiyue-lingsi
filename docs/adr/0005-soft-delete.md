# ADR-0005：软删除与 30 天回收站

- 状态：已采纳（设计阶段）
- 日期：2026-11-27
- 关联：领域模型 D4、INV-11；数据模型 §2

## 背景

当前删除是物理删除：误触即永久丢失，且旧实现连二次确认都没有。
社区/笔记类产品里，误删是高频且不可逆的伤害。

## 决策

1. 帖子、评论、笔记增加 `deleted_at`；查询默认过滤；
2. 删除 = 写 `deleted_at`，UI 立即消失，30 天内可恢复；
3. 每日任务清理超过 30 天的记录（级联清理评论/互动/引用）；
4. 管理员可立即物理删除（需审计）；
5. 取消发布笔记时，帖子走软删而不是删除。

## 后果

- 查询都要带 `deleted_at is null`，索引需要部分索引；
- 计数触发器只在软删时更新（或由服务层统一处理）；
- 需要回收站 UI（M2）；
- 存储略微增长，30 天窗口可控。

## 备选方案

- **立即物理删除 + 二次确认**：仍无法防误操作，放弃。
- **永不删除**：数据与合规负担，放弃。
